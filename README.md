# Компаньон — пациент и врач

Клиент-серверная версия приложения «Компаньон»: пациент ведёт свои дела через
растение-компаньона, а подключённый врач видит его прогресс, назначает задачи
и пишет сообщения.

## Стек

- Node.js + Express — сервер и отдача статики
- Хранилище данных переключается переменной окружения `DATABASE_URL`:
  - задана — сервер подключается к **PostgreSQL** (`pg`), например к
    бессрочному бесплатному проекту на [Neon](https://neon.tech);
  - не задана — используется локальный файл `data.sqlite` через встроенный
    `node:sqlite` (Node ≥ 22.5), ничего внешнего ставить не нужно. Подробнее —
    в разделе [«Постоянное хранение данных»](#постоянное-хранение-данных).
- Два независимых фронтенда на чистом HTML/CSS/JS: `/patient` и `/doctor`

## Запуск

```bash
npm install
npm start
```

Сервер поднимется на **http://localhost:3000**.

- `http://localhost:3000/patient` — приложение пациента
- `http://localhost:3000/doctor` — панель врача

### Если порт занят

Порт задаётся переменной окружения `PORT` (по умолчанию 3000). Скопируйте
`.env.example` в `.env` и поменяйте значение:

```bash
cp .env.example .env
# затем откройте .env и укажите, например, PORT=3100
```

Либо задайте порт прямо при запуске, без файла `.env`:

```bash
PORT=3100 npm start          # macOS/Linux
$env:PORT=3100; npm start    # Windows PowerShell
```

Откройте оба адреса в двух разных вкладках браузера, чтобы проверить связь
между пациентом и врачом. Каждая роль хранит свой идентификатор (`patientId`
или `doctorId`) в `localStorage` своей вкладки — поэтому два адреса в одной
и той же вкладке одновременно не смешиваются.

Файл `data.sqlite` создаётся автоматически при первом запуске (только когда
`DATABASE_URL` не задана — см. ниже). Чтобы начать с чистого листа, остановите
сервер и удалите этот файл (и `data.sqlite-wal` / `data.sqlite-shm`, если они
есть).

## Постоянное хранение данных

По умолчанию (без `DATABASE_URL`) сервер хранит всё в локальном файле
`data.sqlite` — это удобно для разработки, но не подходит для боевого
хостинга без постоянного диска (например Render на бесплатном тарифе стирает
диск при каждом деплое). Для постоянного хранения используйте бесплатный
Postgres на Neon:

1. **Создайте бесплатный проект на [neon.tech](https://neon.tech).**
   Зарегистрируйтесь, создайте новый проект (бесплатный тариф без ограничения
   по времени), и на странице проекта скопируйте **connection string** —
   строку вида `postgresql://user:password@ep-....neon.tech/dbname?sslmode=require`.

2. **Добавьте её в Render как переменную окружения `DATABASE_URL`:**
   зайдите в ваш сервис на Render → вкладка **Environment** → **Add
   Environment Variable** → имя `DATABASE_URL`, значение — connection string
   из Neon.

3. **Туда же добавьте `ADMIN_KEY`** (Render → ваш сервис → Environment → Add
   Environment Variable) — придумайте любую длинную случайную строку. Она
   защищает эндпоинт `DELETE /api/patients/:id` (удаление тестовых
   пациентов, см. раздел [«API для администрирования»](#api-для-администрирования)).
   Без этой переменной эндпоинт удаления полностью отключён.

4. **Сохраните переменные и дождитесь передеплоя** сервиса на Render — при
   следующем старте сервер обнаружит `DATABASE_URL`, подключится к Postgres
   и автоматически создаст все таблицы (`server/migrate.js` запускается на
   каждом старте, создание таблиц безопасно повторять).

Важно: после первого деплоя с новой `DATABASE_URL` данные, которые были в
старом `data.sqlite`, **не переносятся автоматически** — начнётся чистая
база. Для демо-стадии это нормально; если понадобится перенос старых данных,
это отдельная задача (написать скрипт экспорта/импорта).

Локально, без `DATABASE_URL` в окружении, всё по-прежнему работает через
`data.sqlite`, как и раньше — переменная нужна только на хостинге (или если
вы сами захотите разрабатывать против Postgres локально).

### API для администрирования

`DELETE /api/patients/:id` — удаляет пациента и всё связанное с ним
(обязательства, отметки о выполнении, привязку к врачу, дневник настроения,
сообщения от врача, награды и уведомления). Нужен для чистки тестовых
пациентов на демо-стенде.

- Требует заголовок `X-Admin-Key` со значением, равным `ADMIN_KEY` из
  окружения.
- Если `ADMIN_KEY` не задан на сервере, эндпоинт возвращает `404` при любом
  запросе — как будто его не существует. Это осознанная защита по
  умолчанию: без явно заданного ключа удалять пациентов через API нельзя.

## Как это работает

- Пациент при первом открытии `/patient` автоматически получает нового
  «пациента» на сервере, 6-значный код привязки (pairing code) и 8-значный
  код восстановления. Если в браузере уже есть сохранённые данные пациента,
  этот экран не появляется — так же, как раньше.
- Если `localStorage` пуст (новое устройство или очищенный браузер),
  показывается экран выбора: начать заново или ввести код восстановления,
  чтобы вернуть доступ к прежнему пациенту.
- Врач при первом входе на `/doctor` задаёт имя и пароль — они сохраняются;
  при следующих входах нужно ввести то же имя и пароль. Пароль хранится в
  базе данных в виде bcrypt-хеша, сессия — токен в `localStorage` браузера
  врача, сервер проверяет его на каждый запрос к `/api/doctors/*`.
- Врач вводит код пациента на экране «Мои пациенты», чтобы подключиться —
  один пациент одновременно привязан не более чем к одному врачу. Код
  приглашения действует 24 часа с момента генерации; пациент может в любой
  момент сгенерировать новый — старый код сразу перестаёт работать для
  новых подключений (уже подключённого врача это не отключает).
- Список «Мои пациенты» отсортирован по приоритету: пациенты с выполнением
  ниже 50% за последние 3 дня — наверху, с пометкой «Стоит обратить
  внимание».
- Пациент может включить «Показывать врачу дневник настроения» (по
  умолчанию выключено) на экране «Связь с врачом» — только тогда врач
  видит вкладку дневника на детальном экране пациента, и узнаёт о смене
  этой настройки баннером в панели.
- Пациент в любой момент может отключить врача через иконку 🔗 «Связь
  с врачом».
- Приложение пациента опрашивает сервер каждые 20 секунд (`GET
  /api/patients/:id`). Если врач добавил, изменил или удалил задачу, при
  следующем опросе появляется баннер с уведомлением, явно называющим, что
  именно изменилось; тихих правок без уведомления нет.
- Сообщения от врача видны через иконку ✉️ со счётчиком непрочитанных.
- На детальном экране пациента у врача есть кнопка «Печать отчёта» —
  открывает отдельную чёрно-белую страницу для печати/сохранения в PDF
  через системный диалог печати браузера (`window.print()`).

### Коллекция, достижения и другие приятные мелочи

- Вкладка «Коллекция»: несколько видов растений, покупаемых за баллы
  заботы (те же баллы, что и в «Наградах»), плюс 3 редких вида, которые
  выдаются автоматически за серию без пропусков в 30/60/100 дней (с золотым
  акцентом на горшке). Там же — выбор фоновой сцены за горшком (подоконник,
  теплица, балкон на закате), сохраняется как обычная настройка.
- Каждый вид растения — свой силуэт, не перекрашенная копия одного и того
  же рисунка: Незабудка (по умолчанию), Суккулент (компактная розетка
  толстых листьев без стебля), Папоротник (раскидистые резные ветки, никогда
  не цветёт), Кактус (вертикальные сегменты с колючками, цветёт только в
  состоянии «Цветёт») и Плющ (свисающие вниз плети, горшок на подвесной
  полке). Редкие виды переиспользуют эти силуэты со своей палитрой
  («Хрустальный папоротник» — папоротник, «Феникс-цветок» — кактус).
  Во всех 4 состояниях (цветёт / в порядке / вянет / совсем вялое) листья
  каждого вида по-своему наклоняются и меняют цвет; в состояниях «цветёт»
  и «в порядке» листья/ветки едва заметно покачиваются каждый в своей фазе
  (4-6 секунд), в вялых состояниях растение неподвижно. Когда состояние
  улучшается (например, сразу после отметки задачи выполненной), вокруг
  растения на пару секунд появляется мягкое свечение и несколько
  поднимающихся искр.
- Вкладка «Достижения»: 10 достижений (серии 3/7/14/30 дней, первая неделя,
  завершённый курс, подключение врача, дневник настроения, вся коллекция
  растений, использование машины времени). Разблокированные — цветные,
  остальные — приглушённый силуэт без деталей. Новое достижение показывается
  коротким тостом на экране «Питомец», не модальным окном.
- Под статусом растения — вторая строка с поддерживающей фразой,
  подобранной по времени суток и текущему состоянию (без картинного
  бодрячества и без чувства вины), меняется не чаще, чем меняется сама
  комбинация время/состояние.
- На форме добавления задачи — чипы с частыми вариантами (Витамин D,
  Прогулка, Вода, Приём лекарства, Визит к врачу) для быстрой подстановки
  названия.
- В Android-сборке (`mobile-build/`) у каждого напоминания есть кнопки
  «Сделано» и «Отложить на 10 минут» прямо в уведомлении. Обе кнопки на
  секунду открывают приложение, чтобы выполнить действие (Capacitor не даёт
  надёжного способа обработать нажатие полностью в фоне без нативного
  Android-кода) — это осознанный выбор в пользу надёжности, а не тихий сбой.

### Устойчивость к плохой связи и «спящему» серверу

- На бесплатном тарифе Render сервер засыпает после 15 минут бездействия,
  и первый запрос после паузы может выполняться до ~50 секунд. Если любой
  запрос не отвечает дольше 5 секунд, приложение пациента показывает
  спокойный индикатор «Просыпаемся, секунду…» (баннер сверху, а на самом
  первом запуске — полноэкранный) вместо пустого экрана или зависания.
- Если запрос не может достучаться до сервера вовсе (нет интернета, сервер
  недоступен), приложение повторяет попытку с растущим интервалом (3с, 6с,
  10с) в течение до 60 секунд, прежде чем считать это настоящим разрывом
  связи. После этого дальнейшие запросы не ждут заново по минуте каждый —
  они завершаются сразу, пока фоновый опрос сервера каждые 20 секунд не
  обнаружит, что связь вернулась.
- Последнее успешно полученное состояние (список задач, очки, состояние
  питомца) кешируется на устройстве (`localStorage`). Если сервер
  недоступен, приложение показывает этот кеш с ненавязчивым баннером «Нет
  связи — показаны последние сохранённые данные» вместо пустого экрана.
- Кнопка «Сделал» всегда срабатывает визуально сразу же (оптимистичное
  обновление), даже без связи с сервером. Если запрос не удаётся из-за
  отсутствия связи, отметка сохраняется в очередь на устройстве и
  автоматически отправляется на сервер, как только связь восстановится —
  ничего не теряется молча.
- На панели врача у пациента, чьё устройство не выходило на связь с
  сервером дольше суток (по времени последнего успешного запроса от
  приложения пациента, а не по факту выполнения задач), появляется
  нейтральная пометка «Данные могут быть неактуальны» рядом с именем.
- Раз в месяц, при открытии приложения после месяца с 70%+ выполнением
  дел, показывается один раз спокойный экран-подведение итогов «Ваш месяц
  с Незабудкой» с несколькими крупными цифрами (дни подряд, % выполнения,
  завершённые курсы) и одной тёплой фразой — без графиков, закрывается
  одной кнопкой и не повторяется до следующего календарного месяца.

## Структура проекта

```
server/
  index.js     — Express-приложение, статика + API, запускает миграцию на старте
  db.js        — единый асинхронный слой запросов: Postgres (pg) при заданной
                 DATABASE_URL, иначе локальный SQLite (node:sqlite)
  migrate.js   — создаёт все таблицы, если их ещё нет (для обоих движков)
  store.js     — вся бизнес-логика поверх db.js, не знает о конкретном движке
  calc.js      — расчёт «выполнено/просрочено», серий, состояния растения
  routes/
    patient.js — REST API для роли пациента
    doctor.js  — REST API для роли врача
public/
  patient/index.html — фронтенд пациента (веб-версия, отдаётся Express)
  doctor/index.html  — фронтенд врача
  doctor/report.html — печатная версия отчёта по пациенту
mobile-build/  — отдельная сборка пациентской части для Android/Capacitor
  index.html, styles.css, app.js — тот же интерфейс пациента, но как статичные
    файлы без сервера рядом; app.js обращается к API по абсолютному адресу
    (см. раздел «Сборка Android-приложения»)
  icon-source/icon.svg, icon-1024.png — исходник иконки для генерации
    иконок Android
android/       — нативный Android-проект, созданный `npx cap add android`
capacitor.config.json — конфигурация Capacitor (appId, appName, webDir)
data.sqlite    — локальная база данных (создаётся при первом запуске, только
                 если DATABASE_URL не задана)
.env.example   — пример файла с настройками (скопируйте в .env)
```

## Сборка Android-приложения

Пациентская часть может быть собрана в нативное Android-приложение через
[Capacitor](https://capacitorjs.com/). Это отдельная сборка: `mobile-build/`
не подключена к Express и не содержит `/doctor` — только интерфейс пациента,
общающийся с сервером по сети через обычные HTTP-запросы, а не через
локальную статику.

1. **Задеплойте сервер** (`server/`) на любой хостинг с поддержкой Node.js —
   например Render или Railway — и получите его публичный адрес
   (`https://ваш-сервис.onrender.com`). Для постоянного хранения данных
   задайте на хостинге `DATABASE_URL` с Postgres от Neon — см. раздел
   [«Постоянное хранение данных»](#постоянное-хранение-данных); без него
   сервер будет писать в `data.sqlite` на диске хостинга, который на
   бесплатных тарифах обычно не переживает передеплой.
2. **Впишите этот адрес** в `mobile-build/app.js` вместо плейсхолдера —
   в начале файла есть константа:
   ```js
   const API_BASE = "https://ЗАМЕНИТЕ-НА-ВАШ-АДРЕС.onrender.com";
   ```
   Без этого шага приложение на телефоне не сможет подключиться к серверу.
3. **Синхронизируйте с нативным проектом:**
   ```bash
   npm run cap:sync
   ```
4. **Откройте проект в Android Studio и запустите:**
   ```bash
   npm run cap:open
   ```
   В Android Studio нажмите Run ▶ — предварительно подключите телефон по USB
   с включённой отладкой по USB, либо запустите эмулятор Android.

### Иконка приложения

В `mobile-build/icon-source/` лежит исходник иконки — тот же горшок с цветущим
растением, что и на экране питомца пациента: `icon.svg` (векторный оригинал)
и `icon-1024.png` (растровая версия 1024×1024). Чтобы сгенерировать полный
набор иконок и splash screen для Android из этого файла:

```bash
npm install --save-dev @capacitor/assets
npx capacitor-assets generate --android --iconBackgroundColor "#F3EFE6" \
  --assetPath mobile-build/icon-source
```

Эта команда не запускалась заранее — если она упадёт из-за отсутствующих
инструментов, замените иконки вручную в `android/app/src/main/res/`.

### Известные ограничения этой сборки

- `appId` задан как `com.nezabudka.patient` — кириллица (`com.незабудка.*`)
  недопустима в идентификаторе Android-пакета, поэтому сразу использована
  транслитерация.
- `mobile-build/app.js` — это отдельная копия логики пациента, синхронизируемая
  из `public/patient/index.html` вручную (не автосборкой). Если вы меняете
  функциональность пациента в `public/patient/index.html`, перенесите
  изменения и в `mobile-build/` перед следующей публикацией приложения.
- Раздел «Если порт занят» и `.env` относятся только к серверу; мобильное
  приложение всегда обращается по адресу из `API_BASE`, порт сервера должен
  быть отражён именно в нём (обычно 443 для HTTPS-хостинга, порт в URL не
  указывается).

## Известные упрощения демо-версии

- Пациент не аутентифицируется паролем: его личность — это `patientId`,
  сохранённый в `localStorage` браузера. Восстановление доступа на новом
  устройстве работает через отдельный код восстановления, а не через логин
  с паролем.
- Сессия врача — один активный токен на аккаунт: вход с того же имени на
  другом устройстве делает недействительным предыдущий токен (простое
  «одно устройство за раз», без явного списка сессий).
- «Машина времени» (переход на N дней вперёд) у пациента влияет только на
  то, что видит сам пациент; врач всегда видит реальную сегодняшнюю дату,
  в том числе при расчёте приоритета в списке «Мои пациенты».
- Импорт JSON-снимка данных убран (был в чисто-локальной версии) — теперь
